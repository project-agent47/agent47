# 连续会话与版本化材料引用

本增量仅实现 A1：稳定会话入口、轮次历史与显式材料引用。不改变 12-step 执行保护，不增加长任务续跑、网页 wait、扩展系统或账单能力。

## 交互

- 会话标题来自第一轮目标的首行，最长 60 字符，后续目标留在“本轮目标”。侧栏按会话列出最新轮次；历史选择器能返回旧轮次，底部不提供旧轮次聊天发送，提供回到当前轮次入口。
- 新任务可选择单份文件材料，发送首条目标时授权该版本；未发送的选择是 10 分钟临时票据，移除会释放票据，重启失效。
- 当前对话支持选择文件与从右侧已保存成果／用户文件“引用到当前对话”。提案、网页、未支持文档不当作文件材料，避免隐式批准或绕过网页摘录审阅。
- 材料 chips 显示文件名、内容版本、版本检查／显式更新、查看及移除。只在发送时对模型授权，选中或右侧查看不调用模型。
- 用户消息留档对应的版本引用，可再次打开已引用快照。移除仅影响之后的引用，不删除已发送历史或已经进入模型上下文的内容。

## 数据与执行

TaskRecord 添加 materialSnapshots、authorizedMaterialIds，TaskView 添加 conversationTitle、latestRunId、materials。SQLite 增加 material_versions 表，同一版本正文只保存一份，轮次 checkpoint 存指针，不在每轮复制整个文件；读取时恢复引用。现有 schema 1 采用加字段／表迁移；启动时补齐标题，不改消息／工具身份，不复活已完成轮次。latestRunId 从现有 row 顺序计算，后续 Run 继承标题与历史版本。

原始快照只留在主进程的独立版本表；renderer 的材料元信息和模型 catalog 都不包含磁盘路径或完整正文。查看时才把选定正文交给应用 renderer，读取工具结果则按现有消息语义留档，仍会产生历史文本开销。发送写入引用 ID／hash，队列绑定发送时的版本；之后更新或删除 chip 不替换队列中的证据。当前 Run 只在消费队列时新增可读版本，后续 Run 继承已经发送的授权与快照。

readMaterial 是内置、稳定 schema，参数只接受版本 ID、offset、length。它读取已经发送的版本，每次最多 12000 字符，返回完整长度、nextOffset、hash、范围和 partial coverage；不访问实时文件或父目录。压缩后 catalog 仍包含已授权的引用索引，原始消息与快照不丢失，工具配对沿用已有机制。

## 边界与限制

- 单份文本最多 1 MB，同时选择最多 10 份，每个延续会话保存的版本内容合计最多 5 MB。旧版本保留计入上限，暂不自动清理历史材料。
- 发送前检查源版本；变化要求更新或移除，不静默更换。更新创建新 ID，旧 hash／正文继续留档。排队后源文件变化，不替换已经发送的版本。
- 查看已留档版本不依赖源文件仍存在。readMaterial 和快照打开校验内容 hash／bytes；损坏失败关闭，不伪装成原版本。
- 文件选择器是单文件读取授权，不赋予父目录或写权限；现有项目读写、快照及本机执行授权互不改变。
- 新任务未发送的临时票据不跨重启保存；已存在对话的材料、聊天草稿与引用历史持久化，原生应用恢复上次打开轮次。
- 材料仅支持当前文本查看器支持的 HTML、Markdown 与代码／文本；PDF、Office、二进制继续使用系统查看器，不解析入模。
- 尚不支持会话自定义重命名、材料自动后台监视、精确 tokenizer、完整 session tree 或安全沙箱。

## 验收入口

`npm test` 包含 materials.test.ts 的范围／权限、首条消息、队列版本、历史标题迁移和损坏校验。`npm run test:preview` 包含 chips、只读历史 dock 与最新轮次导航。

`npm run test:materials:native` 默认使用模型 fixture，只有工具意图测试注入；原生 picker 返回虚构测试文件，实际文件、IPC、SQLite、runtime、材料工具与 renderer 不替换。以 `AGENT47_MATERIAL_LIVE=1` 和已批准代理运行则使用真实 DeepSeek，不注入意图，不替换工具或 IPC；仅 picker 选取虚构材料。真实模型验收不能替代 Windows/macOS 签名安装与系统安全存储验证。
