# P1c：本轮变动入口、成果来源与日常场景优先级

本增量基于 master `333d4ce`，只连接已有文件快照、成果与证据能力，不增加平行资源库、强制 workflow 或扩展系统。以下契约描述实现边界；测试结果与 PR 状态以对应交付记录为准。

## 日常工作闭环

- **资料整理与报告**：读取资料生成简报；在右侧 Markdown 成果里点击引用，查看当时实际读取的证据。不是重新读取当前文件，也不是再次让模型总结。
- **批量文件修改**：任务顶部“本轮变动”直接展开并定位唯一的变动列表；默认只看正在查看的 Run，可切换本会话全部轮次。文件操作次数与成果数量分别显示，不冒充去重后的文件数。
- **追问修订**：查看 diff、证据和成果都不消费输入区草稿、队列或材料引用，不隐式发消息。恢复沿用底部决策区，查看本身不授权写入。

变动列表是 Task 的 `fileChanges`／`artifacts` 投影，不新建实体或扫描目录。文件显示历史状态、已记录的 hash／字节数；目录没有虚构内容 hash。旧记录没有 hash 时不回填猜测。重复修改同一文件保留多个恢复点；Shell、JavaScript 和远端动作不在文件快照覆盖范围内。

恢复、整轮撤销、冲突检查和目录锁仍使用原 API；不是原子事务，外部修改不会被覆盖。历史轮次显示自己的变动，不把归类或范围切换变成改目录、重放动作或新授权。

## 成果引用的可信绑定

新增可选 `Artifact.evidenceIds`。runtime 保存成果时只冻结正文中出现且已经存在于该 Run 归档的合法实际读取回执 ID；模型不能自行提交这份清单。最多128项，重复 ID 去重。

右侧查看元信息 `WorkspaceTab.sources`／`citationStatus` 从主进程按成果 owner、artifact ID、正文 hash 和归档校验重新生成，不持久化为 renderer 可指定的授权清单。固定成果作为材料打开时仍绑定原成果版本；从磁盘导入的相同 Markdown 只是普通文件，不能凭正文里的 ID 读取其他任务历史。

新增只读 IPC `workspace:artifact-evidence`，输入为 `tabId`、`expectedHash`、`sourceId`。主进程检查目标 Tab 确为已有成果、版本一致、来源在冻结清单中并通过归档校验，然后打开原始只读证据。它不接受左侧当前对话 ID 作为成果 owner，不读取当前源文件、不联网、不调用模型、不更改草稿。

正文中的未知 ID 保持不可点击。缺失或损坏的证据不回退到当前文件／页面，也不搜索其他会话补齐。关闭 Tab、hash 变化或冒用普通文件均拒绝打开。

### 旧版与格式边界

旧成果没有 `evidenceIds` 时不自动推断引用；显示提示，使用“查看来源任务”进入旧轮次核对。新字段可选，无数据库 schema 升级，也不修改旧正文或旧证据。后续如果需要旧版关联，必须另做明确、可审阅的迁移，不在查看时暗中激活。

本批只为 Markdown 成果渲染可点击引用。HTML 仍隔离渲染，不注入应用 IPC；代码源码、普通材料、提案和历史 diff 不因为包含特殊 URI 而获得来源访问。旧证据 Tab 继续只读，不支持改写或把归档摘录冒充完整原文。

来源回执证明实际读取并留档，不保证来源权威、模型结论正确或每句报告都有证据支持。

## 验收范围

- **核心**：清单去重、未知／损坏 ID、缺失正文、旧成果、hash 不符、跨 owner 无回退、只读重启恢复。
- **界面**：顶部入口、当前／全部轮次、空列表、成果打开、未知引用不可点击、草稿不变、窄屏与暗色。
- **原生**：真实文件读写、保存带引用成果、diff、底部恢复；删除源文件和重启后仍打开原始归档。fixture 与真实 DeepSeek 分开记录，不把意图注入算作模型自主调用。
- **回归**：项目资源、选区与 diff、旧来源证据、隔离 smoke，以及 Windows／macOS 原生 fixture。

## 哪些路线图内容应该提前

以下是基于日常场景的产品判断，不是市场覆盖率、承诺工期或已经实现的新功能。仍遵循轻量 Project、明确材料版本、低打断权限和 DeepSeek-only 的既定路线。

| 次序 | 场景与提前项 | 理由与验收边界 |
|---|---|---|
| 本批 | 报告引用核对；本轮文件改动、diff、恢复入口 | 直接连起已实现能力，不增加学习成本；已归档版本不能被源文件变化替换 |
| 下一独立增量，优先 | 回复中断／推理占满输出额度的可理解状态与显式继续路径 | 日常报告“做了工具却没有有效回复”比缺新工具更阻碍使用；保留已完成动作与用量，不自动重放未知请求、不把失败当免费 |
| 紧接，保持小范围 | 资源名称搜索、项目／来源／状态轻筛选，快速返回最近会话 | 资料与成果累积后要找得回来；仍使用统一资源投影，不先做全盘索引、知识图谱或 RAG |
| 并行发布门槛 | Windows／macOS 实际安装、升级迁移与系统安全存储 | CI fixture 不是最终用户环境；先形成可执行验收清单与内部构建，再依据真实证据决定可发布范围 |
| 随使用量提前 | 长会话与变动长列表的分页／虚拟化、启动性能 | 优先避免工作台越用越卡；先建立合成规模与测量基线，不宣称无限历史或已完成全量惰性加载 |
| 有具体案例再推进 | 网页输入兼容性、动作后验证、少量真实站点回归 | 优先保证已有网页工具可靠，不直接扩成任意 JS、密码、视觉坐标或完整浏览器平台 |
| 延后 | 调度、后台记忆、多 Agent、插件市场、模型扩充、账单、Office/PDF 全套编辑 | 当前最主要缺口是任务完成、核对、修订与找回的闭环，不是功能数量 |

建议下一步先做“失败与不完整响应恢复”，再做统一资源的检索与筛选；两个增量分别审阅，避免混成大型重构。新 feature PR 不自动合并，按既定自审、验证和 owner 确认节奏推进。
