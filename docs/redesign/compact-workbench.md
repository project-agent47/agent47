# Agent47：紧凑 Workbench、消息队列与 Skills 生命周期

本增量将产品按“任意用户使用的 DeepSeek-only Agentic Workbench”收紧，不引入新模型、账单或金额预算。基于尚未合并的 PR #2，独立分支 `feat/compact-workbench-queue-skills`；应先处理 PR #2，再合并此增量。

## 交互与运行边界

- **紧凑布局：** 208px 侧栏、44px 顶栏，缩小标题与留白；权限折叠，状态与供应商 input/output/cache rate 保留；实际工具事件以可展开的小行展示，推理默认折叠。
- **固定输入：** 对话记录单独滚动，底部输入位于滚动容器之外。Enter 发送，Shift+Enter 换行，输入法组合输入不触发提交；无“工具后／轮次后”选择器。
- **两阶段队列：** 执行中输入持久保存、在 dock 上方列出，单项可删除。默认等待下一次工具返回，然后合并当时已排队的消息；若当前响应没有工具，则在响应闭合后注入，不无限等待不存在的工具。
- **立即发送：** 中断当前模型请求；其供应商用量如果未完整返回，记为未知，不当作零。已经开始的文件／Shell 操作不强杀，等当前操作返回后注入；未执行的旧工具意图用明确结果闭合，再让模型重规划。
- **暂停状态：** 等审批时普通排队不等于批准；“立即发送”会使原审批失效。askUser 的回答直接配对工具结果。停止／失败的队列保留，但重启不自动复活终态任务；显式立即发送才创建后续 Run。

队列不是文字外观：SQLite 保存内容和工具边界，运行时控制消费，删除只接受尚未消费项；已发送／已删除会给出过期反馈。消息命令仍按 UUID 去重，最多 32 条未处理输入。工具结果未知时先人工核对，不能借队列绕过恢复边界。

## Skills

同名导入进入“审阅更新”，展示旧／新哈希、全部文本文件清单和可展开资源；确认后新版本默认停用，需重新启用。导入票据绑定审阅时的旧哈希，另一个更新已经生效时拒绝覆盖，要求重新审阅。

包内容归档为不可变哈希版本，活动索引原子替换且修改串行。首次 loadSkill 固定具体版本，readSkillFile 读取同版 resources，后续 Run 和重启继承版本；新会话首次加载使用当前启用版本。界面显示已加载 Skill 与版本，不把元信息列表冒充已激活。

停用或卸载会阻止后续工具加载，不能抹掉已经进入模型上下文的文本。卸载是移除活动注册，保留历史版本与审计资料，不宣称磁盘安全删除；旧版本的自动 GC 尚未实现。Skill 仍是指导，不授予文件／Shell／网页权限，不自动安装依赖或执行 scripts；二进制 assets 与在线市场不在本增量。

## 首个网页工具

新增 `readWeb`，仅在对话已授权站点时向模型开放。它不是完整浏览器：公共 HTTPS、443 端口、GET、HTML／文本，最多三次重定向、512KB 响应、24k 字符工具内容、20 秒请求期限；不带登录 Cookie、Authorization 或模型密钥，不执行网页 JavaScript，不点击、登录、下载或提交表单。

每个重定向重新验证授权 origin。DNS 答案检查公共 IPv4 后固定到连接，TLS 仍使用原站点名称验证，拒绝本地／私网／保留网络及混合 DNS。IPv6-only 站点、需要 JavaScript 的页面、非 UTF-8 内容准确转换、企业代理和完整浏览器 takeover 尚未支持。读取中撤销授权会拒绝将该返回内容放入模型上下文；网页文本标记为不可信证据。

公开 GET 也不是“远端无副作用”的普遍保证。不要授权会把 GET 当作操作的业务接口或在 URL 中携带秘密，站点读取日志与已发送请求不能回滚；后续浏览器动作需另建权限／确认契约，不能复用此只读授权。

## 文档交互对照

- **Pi：** RPC 文档提供 steering、follow-up、clear_queue 与 abort；steer 的公开 RPC 边界是当前 assistant turn 的工具调用结束、下一次模型调用之前。本产品按用户要求在当前具体工具返回后合并队列，并闭合剩余旧意图，不声称完全复制 Pi 的所有客户端语义；参考 [Pi RPC 文档](https://pi.dev/docs/latest/rpc-commands)。
- **Claude Cowork：** 公开文档强调进度可见、中途引导，以及消息框中的权限控制；采用可见活动与就近权限入口，不复制云端执行或其自动安全审查承诺；参考 [Cowork 入门](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork)。
- **ChatGPT Work：** 官方文档描述对话内进度、需要输入／登录／确认时暂停以及浏览器接管；采用明确的暂停与交还边界，接管是未来完整浏览器工具需求，不把 HTTPS 抓取冒充接管；参考 [Work 云浏览器说明](https://help.openai.com/en/articles/20001280-using-cloud-browser-in-chatgpt)。
- **Mistral Vibe：** Skills 采用发现／激活／资源读取的渐进展开，并提供启用、编辑、删除和可见激活；文档明确活动对话保留编辑前版本。这里落实哈希固定与活动注册管理，不引入共享工作区权限；参考 [Vibe Skills](https://docs.mistral.ai/vibe/work/skills)。

以上是公开文档的交互与机制对照，不是登录上述产品后逐像素审查，也没有验证竞品内部实现。

## 验收与剩余范围

新增测试覆盖默认排队不打断模型、删除与命令去重、下一工具边界、立即发送 abort、用量未知、Host 不强杀／不重放、停止队列、固定版本升级与重启、过期导入票据、读取中撤销，以及 DNS 固定、私网／跨站重定向、响应大小与失败。

本地 90 项单元测试、8 项预览界面场景、构建／类型检查、lint、Electron fixture IPC／隔离 smoke 和 42 项对比度检查通过；完整 npm audit 为 0。界面测试同时断言 1440px 桌面与 375px 窄窗口的 dock 下边缘，移动端预览不是新增移动 App。

真实 Electron＋DeepSeek 验收返回 `REAL_WORKBENCH_E2E_OK`：模型请求打断、审批期间队列删除／改写、真实 Node utility 工具执行期间默认排队并在返回后自动消费（不点立即发送）、升级审阅／重启后旧资源固定／新会话新资源／界面卸载，以及真实 HTTPS 读取到 Example Domain 后经模型回答并撤销权限。仅原生目录选择器选取临时测试包；模型、工具、IPC 和数据库没有替身。首个 live harness 尝试在响应已结束后点击队列项，发生消费竞争；改为请求进行中立即操作，并把删除放在稳定审批暂停状态分别验证，没有把失败计为通过。

真实模型验收环境仍为 Linux 容器并由测试 harness 使用 `--no-sandbox`。Windows/macOS 原生安装、签名、公证与安全存储、OS 工具沙箱、完整浏览器、session tree、精确 tokenizer、调度、MCP 和多 Agent 协调均不由本增量验收。
