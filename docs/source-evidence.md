# R1：来源证据与历史摘录闭环

本增量把已有读取工具的结果变成可核对的来源记录：DeepSeek 在回答中引用实际读取后的 source.uri，用户点击即可在同一右侧工作区查看当时的摘录、版本与范围。它不是搜索引擎、自动事实验证器、浏览器接管或扩展系统。

## 交互

- **回答引用**：`[材料名称](agent47-source:s0123456789abcdef)` 渲染为紧凑按钮。只有当前会话真实归档的 ID 可点击，未知 ID 显示“无效来源引用”；不把模型提供的任意 URI 变成网页链接。
- **来源列表**：聊天历史顶部的可折叠“来源证据”展示文件名／页面标题、读取时间、版本和原文 UTF-16 范围。没有读过的材料，仅有元信息或执行失败不会创建来源。
- **右侧定位**：引用打开所引范围的只读历史摘录，而非当前磁盘或重新加载网页。没有目录权限、写入、普通输入、模型请求或额外审批；聊天草稿保持不变。
- **网页区分**：证据 Tab 显示原 URL；另有明确的“打开当前网页（重新联网）”按钮，沿用既有公共 HTTPS 校验。这个新网页不是历史证据、不是 Agent 授权，也不会自动入模。
- **版本边界**：源文件／页面变化、删除、Tab 关闭或重启不替换引用正文。不同原文范围分别留档，只有读取时实际返回的内容可作为证据；不把未加载／隐藏／跨 frame 内容算进覆盖范围。

Markdown 的普通外部链接仍不自动开放，远程图片与原始 HTML 不渲染。第一版覆盖回答和来源列表；产物内部的引用绑定、行号高亮、人工事实核对和搜索供应链不在本批。

## 证据契约

成功的 `readMaterial`、`readFile`、`browserRead`、`readWeb` 才创建回执。回执含：

```json
{
  "id": "s0123456789abcdef",
  "uri": "agent47-source:s0123456789abcdef",
  "kind": "material",
  "name": "notes.md",
  "versionHash": "<被读取版本的哈希或页面范围contentDigest>",
  "contentHash": "<实际归档摘录的SHA256>",
  "offset": 100,
  "end": 300,
  "observedAt": "<读取时间>",
  "coverage": "<原工具覆盖声明>",
  "originRunId": "<实际读取轮次>",
  "tool": "readMaterial"
}
```

文件／材料 versionHash 是原始文本版本，包括 BOM 和真实换行。browserRead 的版本使用原有页面／区域 contentDigest，HTTP 只读读取使用实际返回文本的哈希，不冒充服务器资源版本或完整原始 HTML 哈希。contentHash 始终对应归档摘录，范围为所读取文本空间的 UTF-16 偏移，不是网页 DOM、token 或 Markdown 渲染位置。

当前内置读取结果都受界限约束，归档单条最多65536 UTF-16 单元。超出该上限时记录明确的截断声明，不跨 UTF-16 代理对；模型不得引用范围之外的内容。每个会话 lineage 最多128条、正文合计1MB；达到上限后读取仍可成功，但返回 sourceUnavailable，不伪造 URI，也不丢掉原读取结果。

回执证明应用成功获取／归档了这个范围，不证明模型正确理解、引用句与证据语义一致、业务成功、来源真实权威或覆盖全文。引用 ID 与会话的绑定是应用执行边界，不是对恶意本机程序的密码学证明；可信 Shell／Node 仍是系统用户权限。

## 上下文与长对话

每次模型执行默认得到最近32条来源元信息，不自动回灌所有摘录正文。完整历史与来源留档不随 context compression 删除，摘要指令要求保留证据 ID、范围及相关事实，不允许把摘要变成新权限。

新增内置 `readEvidence`，只读取当前会话已有回执：

```json
{"id": "s0123456789abcdef", "offset": 0, "length": 8000}
```

offset 相对归档摘录，length1–12000（默认12000），返回实际 readRange（原文绝对范围）与 nextOffset。没有网页请求或磁盘重读，不创建新来源，也不能把历史时间标成当前观察。支持摘要之后重新核对，但不能仅凭目录元信息证明某句事实。

追问继承来源 ID 与版本，不复活旧工具调用。应用不能保证模型一定引用每句事实、正确选择每个来源或完整保留摘要信息；相关要求由提示与回执工具支撑，缺失或错误 ID 在 UI／主进程被拒绝，而语义核对仍有待后续能力。

## 存储、IPC 与权限

正文保存在 SQLite `source_evidence` 不可变记录中，检查点只保存元信息指针，追问不重复保存正文。旧 schema1 增量创建新表，无来源的老对话保持原样，不根据历史聊天文字补造来源。

读取归档时核对 ID／URI、正文哈希、版本格式、范围、来源类型、工具、观察时间与网页 URL。未知、跨会话或不完整记录拒绝；损坏／缺失正文不以默认数据覆盖。主进程的 `workspace:evidence` 只接受 taskId/sourceId，读取该会话已归档快照；模型不能传入任意本地路径或网页脚本。

证据 Tab 是普通只读文本，不创建 WebContentsView，不共享网页 Node／IPC；不能刷新成当前版本、当材料重新导入扩大授权、编辑或使用系统查看器打开。浏览原网址是另一个显式动作，仍由既有公共站点／网络边界处理。

来源正文与历史引用长期保留，当前没有单独的来源清理设置。移除材料或清理文件恢复备份不删除来源归档；关闭证据 Tab 仅删除查看副本，不能擦除聊天和已留档事实。1MB为会话继承链的正文界限，不是整个应用数据库／模型历史的全局上限；checkpoint 中旧工具结果仍有存储开销。

## 验收边界

单元覆盖实际读取回执、范围／版本、分页、归档上限、无效 URI、正文损坏／缺失、不可变正文只存一次、追问继承、模拟压缩后 readEvidence 与跨会话拒绝。预览用真实鼠标点击验证已知／未知引用、右侧定位、草稿保持、readonly 与暗色窄屏，预览始终使用示例数据。

原生 fixture 使用真实 Electron、Monaco、IPC、SQLite、文件与归档，明确注入读取工具意图；不冒充 DeepSeek。真实材料脚本由 DeepSeek 调用 readMaterial 生成引用，源文件变化／删除后点击仍显示旧证据；重启后调用 readEvidence 再答，来源 ID 与正文保持同一份。

真实网页脚本使用真实 DeepSeek 和原生工具，通过单次点击、有界等待、区域分页，分别引用随机 HEAD／TAIL 所在的实际范围。只有 HTTPS 测试网页响应是 fixture，不把它描述为公网网站兼容率验证；正文不包含密码控件值。查看引用不触发新模型请求。

Windows／macOS 的原生 CI 为 fixture，不等同签名安装、系统安全存储或真模型实机。真实模型在 Linux harness 验证；没有新增多模型、扩展、账单、搜索、Office、Project 或来源语义验证功能。
