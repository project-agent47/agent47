# 长任务暂停、续跑与可验证进展

本批为独立 A2，继续使用 AI SDK ToolLoopAgent 的单步骤输出与持久 TaskRuntime，不引入另一个 agent 框架。DeepSeek-only、材料版本与工具权限不变。

## 状态与交互

- `paused` 是非终态，同一 Run 保存消息、pending 意图、问题草稿、审批绑定、工具结果和用量。完成／失败／停止不能借“继续”复活。
- 手动暂停只中断当前模型请求，usage 未报告则未知。已派发本机／远端操作不强杀；等待结果后在工具边界暂停，结果未知优先走原核对区，不能绕过。
- 暂停时底部显示原因、“补充要求”和“继续本轮”。消息仍可排队／删除，立即发送只提前排序，不解除暂停；若替换旧问题／审批则明确作废。普通补充仍遵守原工具边界，保留人工决定。
- 手动暂停原待回答／审批的任务，继续先回到原决定，不批准动作。主机全局撤权、网页重启撤权及旧引用失效仍有效。
- 继续扩展一个执行窗口，默认 12 个已完成模型步骤；工具 pending 已闭合后才检查窗口上限。步数和 token 记录始终累计，不提供无人值守无限扩窗。
- 重启已暂停任务保持暂停、不调用模型。运行中保存过暂停请求的任务重启也保持暂停；普通未暂停任务仍遵守原检查点恢复策略，不是新增离线常驻能力。

## 进展检测不是业务成功率

记录实际工具结果数、工具错误数、最近工具及时间、窗口序号与模型步骤。`browserClick` 返回派发也只计一个结果，不能计为业务成功。

- 连续三次相同工具输入与同一输出暂停。输入对象按键排序，避免属性顺序变化绕开。
- 有副作用的第三次相同连续工具输入在派发前暂停；不等待第三次写入或点击完成。
- 连续四次工具错误暂停，即使输入不同。
- 继续／消费新的补充要求重置连续检测计数，历史工具数／错误数不清零。不会额外请求付费模型“评估进度”。
- 只检测相邻重复和连续错误，不声称识别所有语义空转、交替循环或保证目标达成。变化中的读取结果不会被当作相同观察。

## 迁移与边界

SQLite schema 1 上增加可选字段，不覆盖旧记录。旧 Run 的工具总数未回算，显示为新增记录之后的计数；历史步骤和 usage 不变。暂停不回滚文件、Shell、远端效果，也不扩大项目／网页权限。

上下文压缩机制及 3 次压缩保护保留；压缩失败、连接失败与非法模型输出仍可作为失败结束，不把所有错误包装为可安全重试。没有调度、云端运行、Office/PDF 解析、新网页等待或扩展系统。

工作流只参考 [Pi 的工具边界 steering](https://pi.dev/)、[Codex harness 生命周期](https://developers.openai.com/blog/codex-as-a-platform) 和 [OpenCode doom_loop](https://opencode.ai/docs/permissions/)。本检测规则是 Agent47 的具体实现，不宣称等同三者完整行为。
