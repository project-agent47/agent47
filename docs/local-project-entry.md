# P1a：日常工作项目、目录授权与资料入口

## 目标与边界

Agent47 是 DeepSeek-only 的本机日常工作台，不是代码 IDE、自动排期系统或强制 workflow。项目用于组织“日常工作、旅行规划、研究资料、家庭事务”等持续主题；无需目录即可先讨论，也无需为每个小任务建项目。本增量实现组织入口，不实现项目共享记忆。

本轮新增项目创建、改名、置顶、归档／恢复；会话归类；可复用目录授权；右侧目录文件和项目成果入口；按项目保存查看标签与最近打开轮次。现有底部消息队列、决策区、多轮对话、自动快照、来源证据和网页权限继续使用。

没有新增模型、插件、MCP、扩展注册接口、自动排期、后台记忆、账单或 Office 支持。项目说明、固定材料、@ 引用和统一项目上下文属于 P1b，尚未实现。

## 参考取舍

- NewMax：吸收项目内多会话、文件列表先行、预览按需展开，以及低频设置折叠；不照搬四类计划页、自动排期或默认完全访问。公开文档参考：[项目](https://newmax.cc/docs/features/projects)、[工作区](https://newmax.cc/docs/features/workspace)、[对话](https://newmax.cc/docs/features/chat)、[设置](https://newmax.cc/docs/features/settings)。
- Pi、Codex、OpenCode：继续采用目标驱动执行、低打断、明确运行边界，不加入强制任务图。参考入口：[Pi](https://pi.dev/)、[Codex](https://github.com/openai/codex)、[OpenCode](https://opencode.ai/docs/)。
- Agent47：目录读写一次授权与自动快照保持默认；查看文件和浏览网页不自动把内容交给模型，项目组织也不等于扩大权限。

这些是设计取舍与公开资料对照，不是登录后的横评或竞品安全审计。DeepSeek Harness Desktop 的指定仓库仍未确定，本轮没有选择同名第三方 fork。

## 交互

### 项目与会话

左侧“工作项目”提供创建、置顶项目、近期项目、归档项目和全部会话。项目切换显示该项目会话，全部会话入口保留跨项目查找；现有未归类会话和其执行目录不迁移、不删除。

项目头部只显示名称、目录状态与可展开设置。会话归类收进任务头部菜单，避免增加常驻行挤压底部输入区。归类只允许整段会话所有轮次已结束且不存在未知操作效果；归类不改写旧会话的目录、历史材料或权限。活跃和暂停会话须先结束再移动。

归档是组织操作：保留聊天、文件、成果和既有授权，也不会停止正在运行的任务。已归档项目不能新建会话或换目录，仍可撤销目录权限。若恢复时原目录已绑定另一活动项目，先撤销旧授权再恢复。

### 目录授权

项目设置使用原生文件夹选择器取得不可伪造的 folderGrant，再展示完整目录、读写模式与风险，由用户确认授权。目录可选：没有目录的项目仍能讨论和使用显式文件材料。

新会话可以复用项目目录和文件模式，但不继承其他会话聊天、材料版本、网页授权或 Shell／JavaScript 免确认信任；新会话 hostMode 仍为 ask。全局本机执行开关和已有可信对话入口保持不变。

更换目录要求先结束该目录绑定的活动会话，包括暂停任务。撤销会提高授权版本，并请求活跃任务安全暂停；已经派发的操作不回滚，也不强杀。旧会话和后续轮次保留原目录绑定，不能因重新授权或归类而暗中换到新目录。重新授权后应新建会话。

同一个规范化目录不得同时绑定两个未归档项目。归档本身不撤销既有授权，这不意味着目录有进程隔离或独占写锁。

### 文件与成果

右侧“项目文件与成果”先展示文件列表，点文件才进入已有 HTML／Markdown／只读 Monaco 查看器；支持进入子目录、返回、刷新和每页 200 项。只枚举当前一层，不递归索引、不自动读正文；底层 readdir 仍一次取出当前目录的全部条目，不宣称百万文件规模有界扫描。

隐藏条目和符号链接不显示；打开沿用敏感路径、越界和真实路径检查。打开不启动模型请求，不隐式把父目录或文件内容注入模型。格式支持和系统查看器边界沿用现有工作区。

项目成果汇总已归类会话的已保存成果，可查看，也可回到原轮次；不自动移动磁盘文件。提案预览与实际保存批准保持分离。

### 切换与恢复

项目各自保存右侧标签与布局、最近打开轮次。切换销毁旧原生视图并撤销网页临时授权，网页暂停；重启也不自动联网。处于派发边界的网页工具要求先完成或安全暂停，不能把动作目标偷换到另一工作区。

现有会话输入草稿持久化并可重启恢复；新任务尚未发送的目标和材料选择仅在本次应用运行内按项目保留，未增加重启持久化。材料 ticket 仍按既有 10 分钟／重启失效，不应把暂存选择当作永久材料绑定。

## 数据与执行契约

- projects.db：主进程拥有的 SQLite schema1；存储项目元数据、revision、rootRevision、会话 membership、幂等创建请求与最近打开轮次。
- TaskRecord：新增 originProjectId、rootProjectId、rootProjectRevision。原始项目归属用于创建中断修复；执行授权绑定独立于可变会话归类。
- TaskStore schema2：原 checkpoint 与材料／证据档案仍是事实源，新增派生 task_views，供列表查询使用，不在每次列表刷新时重新 hydrate 全部模型消息和档案。冷启动仍完整验证历史，未实现完全惰性启动或宣称大型档案性能已验收。
- runtime：项目文件工具及本机执行在准备／派发边界检查授权版本。撤销后旧动作被阻止；app 自有成果库 writeArtifact、已授权材料档案 readMaterial 与历史证据 readEvidence 不误绑项目目录。
- workspace-project-{id}.json：每项目独立查看状态；无项目保留旧 workspace.json。异步保存捕获当时的路径，防止旧状态写入新项目文件。

IPC 包含 projects:view/create/update/bind/assign/switch/files/open-file。参数由主进程严格校验；绑定只接收原生目录选择器签发的 grant，不接受任意 renderer 提交的绝对目录作为授权。权限不是由模型输出决定。

项目创建使用 clientRequestId 幂等化；相同 ID、不同内容拒绝。修改采用 expectedRevision，过期设置要求重新审阅。创建后断电造成 membership 未保存时，启动依据 originProjectId 修复；显式取消归类保存 tombstone，不会被启动修复重新归类。

## 迁移与回退

首次升级 schema1 时，通过 SQLite VACUUM INTO 生成 tasks.db.before-schema2 一致性备份；首次初始化项目存储另保留 tasks-before-projects.db。没有复制正在使用的 WAL 数据库文件冒充一致性备份。

schema2 标记使旧 runtime 拒绝打开升级后的数据库，而不是忽略新授权边界。回退需保留完整当前数据目录，再在关闭应用后恢复升级前备份；升级后新增的数据不会出现在升级前备份里。不要直接删除 projects.db 或把 schema 数字改回 1。

若 checkpoint 已包含项目绑定但 projects.db 缺失，启动失败并要求恢复原项目数据，不能生成空项目默认值替代。数据损坏和未知 schema 同样失败关闭。task_views 是派生缓存，启动从 checkpoint 重建；普通 checkpoint／视图写入不是跨数据库原子事务。

## 验收与已知限制

单元覆盖幂等、revision、归类／执行目录分离、撤销授权围栏、归档恢复冲突、目录分页与路径拒绝、迁移备份、创建中断修复、取消归类 tombstone 和 runtime 阻止撤销后写入。

UI 覆盖项目创建与授权、查看无隐式发送、跨项目标签与草稿、深色窄窗口；既有 dock 队列测试维持原先的窗口底边断言，没有为新布局放宽标准。原生 harness 覆盖真实 IPC、数据库、文件、快照与重启；fixture 模式明确标记模型和工具意图注入。

真实 DeepSeek 模式不注入工具意图：读取 notes.md、创建 brief/周报.md 并保留随机证据，接着新建独立会话直接回答；仅原生目录选择器返回虚构测试目录。Linux harness 的 --no-sandbox 不代表生产沙箱验收。Windows/macOS CI 是原生 fixture，不等同真模型实机、签名安装或系统安全存储验收。

后续 P1b 应继续面向日常工作：版本化项目说明、用户显式固定材料和 @ 选择入口，按需读取，不自动共享所有聊天或递归把目录塞进上下文。另行评估大型档案列表和冷启动性能，不把本轮缓存优化称作完整性能解决方案。
